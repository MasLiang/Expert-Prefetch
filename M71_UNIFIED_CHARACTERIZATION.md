# M7.1 Unified Cross-Layer Characterization

## Scope

All main CSVs and figures are generated by `UnifiedSequenceSimulator` with a
three-layer, deterministic, B=1 Top-K=4 workload.  Results are tagged
`unified_cross_layer`; no main row uses `synthetic_prediction_ready_override`.
The hardware mode is `controlled_synthetic_hardware`, not measured VEK280.

## Reproduction

```bash
python examples/m71_unified_characterization.py --smoke
python examples/m71_unified_characterization.py --full
python examples/m71_make_figures.py --input-dir results/m71_unified_characterization/raw
```

The first command writes a small subset.  The full command writes all required
raw CSVs, tables, exact figure-data CSVs, PNG/PDF figures, and the manifest.

## Interpretation rules

`realized_lead_cycles` is an observed target-Router-resolve minus
predictor-ready value.  It is not injected.  Full, uniform-prefix, and
ranked-prefix policies reuse the same predictor trace for each controlled
comparison.  `full_vs_prefix_explanation.csv` uses measured counters only;
its labels are descriptive rather than claims of universal optimality.

## Findings to read from generated tables

The source-milestone study shows earlier source availability increases measured
lead opportunity, but can also change contention.  Perfect prediction is a
positive control for full-expert prefetch.  The quality, budget, OCM, channel,
and Top-K tables separately expose useful/wasted bytes, readiness, OCM
rejections, and non-preemptive future-speculation demand blocking.  Higher
Recall@M must be interpreted jointly with useful bytes before Router,
critical-start delays, and blocking; it is not treated as sufficient for lower
latency.

## Boundaries

This is a unified-simulator mechanism study.  It does not model measured
VEK280 behavior, attention/KV cache, continuous batching, persistent Expert
cache, physical NoC, LPDDR bank effects, power, or predictor hardware.
VEK280 conclusions require an explicitly tagged theoretical profile followed
by measurement/calibration.

## 1. Executive Summary

The generated tables show real source-derived lead time, finite-OCM admission,
and non-preemptive future-DMA interference on one unified timeline.

## 2. Experimental Scope

`controlled_synthetic_hardware` isolates mechanisms. `vek280_theoretical` is
an unmeasured projection with 304 physical/logical AIE tiles, 102.4 GB/s
theoretical memory bandwidth, and a MAC=2-op 202 TOPS input convention.

## 3. Realized One-Layer-Ahead Lead Time

See `source_milestone_study.csv`; milestone is the only varied input.

## 4–10. Policy, Quality, Budget, OCM, Channel, Top-K, Opportunity

Use the identically named raw CSVs.  Full expert is retained as the strong
positive-control baseline; prefix policies trade traffic/OCM pressure against
startup coverage.  No winner is hard-coded.

## 11. Critical-Path Analysis

`per_expert_timing.csv` records true Expert start/finish, router-to-start,
memory wait, startup readiness, and critical completion flag.

## 12. M6 versus M7 Semantics

M6 target-local ready time is an isolated microarchitecture control. M7.1 lead
is source milestone plus latency and is therefore the architecture-level result.

## 13–15. Robustness, Synthetic Dependence, Calibration

Robust mechanisms: demand priority, non-preemptive active speculation, finite
OCM admission, and source-derived lead. Numeric crossovers require calibrated
DMA setup/bandwidth, AIE scaling, OCM behavior, and measured predictor latency.
